#01 VERIFICATION PREREQUISITES & HARDWARE PERMISSIONS

5-Point Verification Checklist

Ensure each prerequisite is satisfied to enable autonomous background synchronization between iOS and your Mac.

STEP 01 IDENTITY
Identical Apple ID
Your iPhone and your Mac must be signed into the same Apple ID. The app writes into the private ubiquity container iCloud~com~hermes~HermesCompanion which only synchronizes between devices sharing your account.
STEP 02 STORAGE
iCloud Drive Enabled
On iPhone: Settings → [Your Name] → iCloud → iCloud Drive must be toggled ON.
On macOS: System Settings → Apple Account → iCloud → iCloud Drive must also be enabled.
STEP 03 CRITICAL
Location Permission: "Always"
In iOS Settings, location access must be set to "Always" (not just "While Using the App"). iOS suspends background wakes, cell-tower monitoring, and stationary geofences if set only to "While Using".
STEP 04 HEALTH & MOTION
Apple Health Authorization
When prompted by the app, authorize read access for Sleep Analysis and Workouts, plus Motion & Fitness. Without this, health snapshots will remain empty.
STEP 05 HOST OS
macOS for iCloud / Any OS for Direct Sync
When using Apple iCloud, the host must be native macOS where CloudDocs mirrors files to ~/Library/Mobile Documents. When using Direct Connection, Hermes runs on any OS (Linux, Windows, WSL, Docker, macOS) via the built-in HTTP daemon (companion.py --serve).

Target Settings State
Verified configuration: Smart Always profile active, dynamic stationary geofence set to 100m, and distance filter set to 30m.

Omitting battery and fine-grained velocity eliminates constant sensor polling and prevents fingerprinting. Your agent only needs qualitative motion classification (stationary, walking, running, cycling, automotive) and arrival context to understand your day.

No. This is the primary architectural differentiator of Hermes Companion compared to other apps.

Other companion or self-hosted agent tools require persistent VPN profiles on iOS (Tailscale, WireGuard), open router ports, or third-party reverse tunnels (Cloudflare, ngrok). Those tunnels prevent the iPhone from deep sleeping, drain battery rapidly in your pocket, drop sockets when switching between Wi-Fi and 5G cellular, and create firewall headaches.

With Apple iCloud mode, Hermes Companion requires zero tunnels, zero VPNs, and zero open ports. The iOS app writes files to its local flash sandbox, and Apple's native CloudDocs system synchronizes them to your Mac via your personal Apple ID. With Direct Connection mode, the phone talks directly to your host over local LAN or standard HTTPS reverse proxy with zero persistent tunnels required.

Direct Connection allows you to run Hermes on Linux, Windows, WSL, Docker, or macOS without relying on Apple iCloud:

  1. Zero-Friction Chat Pairing: Simply tell your agent in chat (Telegram, Discord, Web): "Connect my iPhone" (or "pair the companion app"). The agent generates a pairing QR code in one turn and replies with the image.
  2. Terminal Pairing Command: Run python3 ~/.hermes/skills/hermes-companion/scripts/companion.py --pair --qr-file /tmp/hermes-companion-pair.png (add --endpoint https://<public-host> if using a reverse proxy).
  3. Scan in App: In Hermes Companion, navigate to Settings → Sync Provider → Direct Connection → Scan Pairing QR Code and point your camera at the screen. The host URL and secure Keychain Bearer token configure automatically.
  4. Start Host Daemon: Run python3 ~/.hermes/skills/hermes-companion/scripts/companion.py --serve --port 8787 on your host machine. Telemetry and Post letters sync to ~/.hermes/hermes-companion/data/.
